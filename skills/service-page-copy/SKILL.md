# 網站頁面銷售文案 Skill

把客戶的產品/服務寫成「讓陌生訪客 30 秒內看懂、3 分鐘內想行動」的網頁文案。重點：客戶視角、痛點驅動、步驟清楚、行動明確。

---

## 三大寫作鐵則（最重要）

違反任一條都要重寫：

1. **客戶視角，不是公司視角** — 第一句講讀者的問題，不是「我們是一間專注於 X 的公司」。文案中「你」出現次數要多於「我們」。
2. **痛點先行，方案後到** — 先讓讀者點頭「對對對我就是這樣」，再給解法。沒戳到痛點的文案讀者會直接關掉。
3. **具體勝過華麗** — 數字、時間、對比、案例優先於形容詞。「省 4 小時」勝過「大幅提升效率」。

---

## 第一步：釐清讀者與賣點

動筆前先回答這 5 個問題，回答不出來就回頭問使用者：

### 1. 讀者是誰？
具體到行業、規模、角色。例：「20–60 歲的中小企業主，特別是診所、餐廳、工作室老闆」，不是「對網站有興趣的人」。

### 2. 讀者現在用什麼？卡在哪裡？
他們現在的解決方案是什麼？為什麼不滿意？這就是痛點。
- ✅「他們現在用 WordPress，每月要花 4 小時更新外掛、付 NT$ 800 主機費、還擔心被駭」
- ❌「他們需要一個網站」

### 3. 讀者想達到什麼？
要的不是產品本身，是產品幫他們達成的事。
- ✅「他們要的是能讓 Google 搜得到、訪客打電話來、不用每月維護的官網」
- ❌「他們要的是一個快速、漂亮、安全的網站」（這是你想賣的，不是他們想要的）

### 4. 我（產品/服務）解了什麼？
聚焦 1-3 個核心解法，不要把所有功能都列。

### 5. 我為什麼可信？
數字、案例、年資、名單、實測截圖。沒有就老實說「新平台，前 N 名免費試用」。

**沒答案就用 AskUserQuestion 問**。不要腦補客戶數據（價格、客戶數、案例公司名）。

---

## 第二步：頁面結構與文案產出

### 頁面類型對應結構

| 頁面 | 核心任務 | 必備區塊 |
|-----|---------|---------|
| **首頁** | 30 秒讓人懂你做什麼、為什麼選你 | Hero / 痛點對照 / 三大優勢 / 運作步驟 / 案例或社證 / CTA |
| **服務/方案** | 看清楚有哪些服務、價格、適合誰 | 開場一句話 / 服務清單 / 價格表 / 流程 / FAQ / CTA |
| **關於** | 為什麼可信、為什麼選你 | 品牌信念 / 故事 / 價值觀 / 數據 / 團隊 / CTA |
| **聯絡** | 把詢問門檻降到最低 | Hero（降焦慮話術）/ 多管道 / 表單 / 期待回應時間 / FAQ |

---

### Hero 區塊（最關鍵的 5 秒）

讀者只看標題跟副標就決定要不要往下看。

**標題公式**（擇一）：

| 公式 | 範例 |
|------|------|
| 痛點 + 解法 | 不用學 GitHub，也能擁有比 WordPress 快 5 倍的官網 |
| 結果承諾 | 5 天上線、零維護、月費歸零的中小企業官網 |
| 問句 + 隱含解答 | 你的 WordPress 每月在燒你多少時間？ |
| 對比反差 | 別再為一個介紹網站養一台主機 |
| 角色 + 痛點 | 給診所老闆的官網：寫文章像 LINE 一樣簡單 |

**副標規則**：
- 1-2 句，補充標題沒講完的部分
- 至少 1 個具體名詞或數字（工具、行業、價格、時間）
- 不要重複標題的字

**範例**：
> 標題：填表 → AI 寫文案 → 一鍵上線
> 副標：jhost 把架站從 2 個月縮成 2 天。沒主機費、沒外掛要更新、SEO 內建。給中小企業主用的純靜態網站平台。

**Hero 禁區**：
- ❌「歡迎來到 jhost」
- ❌「我們是一間專注於 X 的公司」
- ❌「打造卓越的數位體驗」
- ❌「擁抱未來、創造可能」

---

### 痛點對照（讓讀者點頭）

把舊方案的痛 vs 新方案的爽，做成左右對照。**讀者最容易在這段決定要不要繼續看**。

**對照表範例**：

| 用 WordPress | 用 jhost |
|------------|---------|
| 每月外掛更新 5-10 次 | 完全零維護 |
| 主機 + 外掛訂閱 NT$1,000+/月 | 月費歸零（CF Pages 免費） |
| Yoast / RankMath 要設定半天 | SEO 內建、AI 自動產 meta |
| 3 秒以上載入 | 0.5 秒以內 |
| 每年都有資安漏洞 | 沒資料庫，沒得駭 |

**寫對照表的訣竅**：
- 左邊用讀者「現在的痛」，右邊用「你的解法」
- 兩邊都要具體（次數、金額、秒數）
- 4-6 列剛好；超過 8 列開始無聊

---

### 運作步驟（解除「會不會很難」的疑慮）

這是用戶提到「步驟清楚明白」的核心。最多 5 步，每步 1 句說做什麼 + 1 句說好處。

**範例**：

> **STEP 1 申請帳號**
> 填表 5 分鐘，不用綁卡。我們審核 1 個工作天，確認後寄登入信。
>
> **STEP 2 提供文案與偏好**
> 告訴我們你的行業、品牌調性、要哪些頁面。沒寫好沒關係，AI 會幫你補。
>
> **STEP 3 AI 輔助設計頁面**
> 系統用我們預訓練的設計風格，產出 2-3 個版型方向。你選一個，30 秒生成。
>
> **STEP 4 登入後台寫文章**
> Markdown 編輯器 + 即時預覽。寫一篇文章 5 分鐘，按發布 30 秒上線。
>
> **STEP 5 SEO 自動處理**
> Sitemap、結構化資料、社群分享卡片，全部自動生成。你只管寫好內容。

**步驟撰寫規則**：
- 每步動詞開頭：「申請帳號」「提供文案」「選版型」「寫文章」「自動 SEO」
- 每步加時間或結果：「5 分鐘」「30 秒」「自動」
- 不要寫太細的子步驟（「點 A 按鈕、再點 B 按鈕」），那是手冊不是文案

---

### 適用 / 不適用（誠實界定範圍）

最有說服力的反而是這段。明確講「不適合誰」會讓「適合的人」更相信你。

**範例**：

> **適合用 jhost 的網站**
> ✅ 診所、牙醫、復健所
> ✅ 餐廳、咖啡廳、酒吧
> ✅ 律師、會計師、顧問
> ✅ 設計師、攝影師個人品牌站
> ✅ 任何「介紹 + 文章 + 聯絡」為主的官網
>
> **建議用 WordPress 的網站**
> ❌ 電商（要金流、庫存、訂單）→ 用 WooCommerce
> ❌ 會員制 / 線上課程 → 用 MemberPress
> ❌ 論壇 / 社群 → 用 bbPress
>
> 不知道適不適合？寄信告訴我們你的需求，30 分鐘免費諮詢。

---

### CTA 區塊（讓讀者馬上行動）

最後一定要明確下一步。

**主 CTA 規則**：
- 動詞開頭：「立即申請」「免費諮詢」「看版型」
- 講清楚會發生什麼：「填 5 分鐘表單」「30 分鐘 Zoom 通話」
- 不要兩個 CTA 同等重要 — 主+次：「立即申請 / 或先看版型展示」

**降焦慮話術**（放在 CTA 旁邊）：
- 「免費諮詢，不綁約」
- 「前 14 天可全額退款」
- 「1 個工作天內回覆」
- 「不用綁信用卡」

## 各頁特殊規則

### 首頁特別重點
- Hero 之後 3 秒內要讓讀者看到「對我有什麼好處」，不是「我們公司有多厲害」
- 至少 1 段社會證明（「30+ 客戶」「平均 PageSpeed 99 分」「服務 6 年」）
- 結尾 CTA 一定要再出現一次，不要逼人滾回去

### 服務頁特別重點
- 每個服務都要有：**做什麼 / 給誰 / 多少錢 / 多久**
- 價格寫不出來就寫「NT$ XX,XXX 起」，比「請洽詢」好
- 加一個「不確定要哪個？」的 fallback CTA

### 關於頁特別重點
- 不要寫「我們的故事」流水帳（成立年份、團隊規模、辦公室搬家）
- 寫「我們為什麼相信這件事」+「為了這件事我們做了什麼」
- 數字段一定要有（成案數、客戶數、年資、PageSpeed 平均分）

### 聯絡頁特別重點
- 第一句要降焦慮：「初次諮詢完全免費」「我們不會狂打電話騷擾」
- 表單欄位越少越好（4-5 個就好），不要列 12 個必填
- 提供至少 2 種聯絡方式（表單 + Email + LINE 任挑兩個）
- 寫「我們會在 X 小時/工作天內回覆」（具體！）

## 文案技巧

### 1. 客戶視角的「你」

每段都檢查：講的是「你會得到什麼」還是「我們提供什麼」？

| 公司視角（爛） | 客戶視角（好） |
|--------------|---------------|
| 我們提供完整的 SEO 設定 | 你的網站第一天就被 Google 收錄 |
| 我們使用 Astro 框架 | 你的訪客感覺像滑 IG 一樣順 |
| 我們有 30+ 客戶 | 你會跟 30+ 個跟你一樣的老闆站在同一邊 |

### 2. 動詞優於名詞

用動詞讓文案有節奏感。

| 名詞化（沉悶） | 動詞化（有力） |
|--------------|---------------|
| 進行網站的優化 | 把網站變快 |
| 提供 SEO 的設定 | 教 Google 認識你 |
| 完成內容的部署 | 把文章送上線 |

### 3. 對比優於形容詞

| 形容詞（空泛） | 對比（具體） |
|--------------|------------|
| 載入速度極快 | 從 3 秒降到 0.5 秒 |
| 維護成本低 | 月費歸零 |
| 操作很簡單 | 寫一篇文章 5 分鐘 |

### 4. 排除句的力量

「不需要 X」「不用 Y」比「具備 X」「擁有 Y」更有衝擊力。

- ✅ 「不用學 GitHub、不用付主機費、不用擔心被駭」
- ❌ 「具備自動部署、免費託管、安全防護等功能」

### 5. 證據比承諾大

| 承諾（要證據才信） | 證據（自帶說服力） |
|------------------|------------------|
| 我們提供極速網站 | 30+ 客戶網站平均 PageSpeed 99 分 |
| 安全是我們的優先 | 平台上線 18 個月，0 次被駭紀錄 |

## 反 AI 味 / 反空話檢查

寫完逐項檢查，任一項出現都要改。

### 互聯網黑話（職場術語）— 全部刪掉

| 避免 | 改用 |
|------|------|
| 賦能 | 幫助、讓你能 |
| 痛點 | 問題、煩惱 |
| 閉環 | 完整流程 |
| 沉澱 | 累積 |
| 賽道 | 領域、產業 |
| 擁抱 | 採用、用 |
| 標誌著 | 代表 |
| 助力 | 幫 |

### 空話形容詞 — 加具體或刪掉

「卓越的」「優質的」「全方位的」「一站式的」「專業的」「精緻的」「極致的」「頂級的」

每個都要問：能換成數字、案例、對比嗎？不能就刪掉。

### 公司視角開頭 — 改寫

❌「我們是一間 / 我們致力於 / 我們專注於 / 我們堅信」
✅ 改成「你」開頭，或「對 [讀者角色] 來說，[痛點]」開頭

### 結尾套話 — 禁用

「讓我們攜手共創未來」「期待與您合作」「相信透過我們的努力」「未來可期」

換成具體下一步：「按下面按鈕填表，我們明天就回你」

### 形容詞濫用 — 砍

形容詞每段超過 3 個就過量。動詞跟名詞才扛得住閱讀的重量。

## 完成後自我檢查

逐項勾選：

**結構**
- [ ] Hero 標題在 30 字內，副標補強而不重複
- [ ] 第一個區塊就點到讀者痛點（不是介紹自己）
- [ ] 有「運作步驟」段落，最多 5 步
- [ ] 有「適用/不適用」段落（如適用）
- [ ] 結尾有明確 CTA + 降焦慮話術

**文案**
- [ ] 「你」出現次數 > 「我們」次數
- [ ] 每個區塊至少 1 個具體數字或對比
- [ ] 動詞開頭的句子 > 名詞開頭的句子
- [ ] 至少 1 個「排除句」（不需要 / 不用 / 不必）
- [ ] 至少 1 個對比表（前 vs 後 / 競品 vs 你）

**反 AI 味**
- [ ] 沒互聯網黑話（賦能、痛點、閉環、賽道）
- [ ] 沒空話形容詞（卓越、優質、極致、頂級）
- [ ] 沒「我們是一間 / 我們致力於」開頭
- [ ] 沒「攜手共創 / 未來可期」結尾
- [ ] 形容詞每段不超過 3 個

**轉換**
- [ ] CTA 動詞開頭，不是「了解更多」這種無感按鈕
- [ ] 主 CTA 講清楚下一步會發生什麼
- [ ] 至少 1 處社會證明（數字、案例、年資、客戶名）

## 文案產出格式

把每頁文案存成獨立 Markdown 檔，方便客戶直接拷貝到 CMS 或 Astro 頁面。

**檔案結構建議**：
```
project-copy/
├── home.md          首頁
├── services.md      服務頁
├── about.md         關於頁
├── contact.md       聯絡頁
└── README.md        頁面總覽 + 風格說明
```

**每個檔案的內部結構**：
```markdown
# [頁面名稱]

> 路徑：/services
> 用途：讓潛在客戶看清楚有哪些服務、價格、適合誰
> 主 CTA：立即申請
> 次 CTA：先看版型

---

## Hero
[標題]
[副標]
[主 CTA 按鈕文字] | [次 CTA 按鈕文字]

---

## [區塊名稱]
[內文]

---

(每個區塊都用 H2 分開，方便對應到網頁實作)
```

這個格式讓設計師 / 工程師可以一眼看到「哪段文字放在哪裡」，不會搞混。
